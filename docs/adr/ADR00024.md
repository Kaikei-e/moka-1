# E2E を Hurl + シェルスクリプトから Playwright へ全面移行し、ランナーを1つに統一する

## Context

E2E は 3 つの実行系に分裂していた。

| 実行系 | 対象 | 実体 |
|---|---|---|
| Hurl(`.hurl` 11 本) | moka-core の HTTP API・Plecto エッジ | 宣言的 DSL |
| bash(`*_e2e.sh` 6 本) | Hurl で表現できない手順 | `curl` + `jq` + `docker compose` + `openssl` |
| Playwright(`.spec.ts` 8 本) | moka-web の UI | TypeScript |

Hurl 自体は宣言的で読みやすいが、**「静的なリクエスト列」以上のことが何も書けない**。その結果、シナリオが 2 ファイルに割れる構造が定着していた —— bash が「配信フィクスチャを差し替える」「DB を直接いじる」「llm を止める」といった状態遷移を担当し、最後のアサーションだけを Hurl に委譲する。`scheduler_e2e.sh` → `scheduler_poll.hurl`、`enrich_e2e.sh` → `enrich_poll.hurl`、`dedupe_no_304_e2e.sh` → `dedupe_no_304.hurl`、`rag_failsoft_e2e.sh` → `rag_failsoft.hurl`、`qa_context_relevance_e2e.sh` → `qa_context_relevance.hurl`、`edge_auth_e2e.sh` → `edge_auth.hurl` の 6 組すべてがこの形をしている。1 つのシナリオを読むのに 2 ファイルを往復する必要があり、変数の受け渡しは `--variable` 経由の文字列に退化していた。

具体的に効いていたコスト:

- **表現力の天井**。SSE の検証が `body contains "event: sources"` の部分文字列一致にしかならず、`sources → delta → done` という**順序**の契約を表明できていなかった(`qa.hurl` #4、`rag_failsoft.hurl` #3)。`auth.hurl` の冒頭コメントは「WebAuthn の儀式完走は Hurl では出来ない」と自ら限界を記録している
- **健全性の暗黙依存**。`dedupe_no_304_e2e.sh` は「内容を変えずに `touch` すれば ETag が変わる」ことに依存していたが、nginx の ETag は `"%xT-%xO"`(mtime の time_t と Content-Length の16進)で **秒精度**。同じ秒内に 2 回 touch して長さが同じなら ETag は変わらず、「条件付き GET が効かない再取得」という前提が崩れたまま**テストが誤って通る**窓があった。実際にはスクリプトの実行に十分な時間がかかっていたため露見していなかっただけで、依存としては不健全
- **ツールチェーンの重複**。ローカルでもCIでも Hurl 8.0.1 のインストールが要り、`jq` / `openssl` / `curl` にも依存していた。型検査も lint も無く、`e2e/hurl/**` はどの CI パリティにも掛かっていなかった
- **CI での取りこぼし**。`e2e/README.md` は 8 ステップの手順を書いていたが、CI が実際に走らせていたのは hurl 4 本 + `scheduler_e2e.sh` のみ。`search` / `qa` / `dedupe` / `enrich` / `qa_context_relevance` / `rag_failsoft` は CI で一度も走っていなかった。ステップを足すたびに CI 側の列挙を手で同期する必要があり、それが実際に破綻していた

UI 層は既に Playwright で書かれており、同じ言語・同じアサーション語彙・同じレポートで API 層も書けるなら、実行系は 3 つも要らない。

## Decision

**E2E の実行系を Playwright ひとつに統一する。** Hurl と `*_e2e.sh` を全廃し、`e2e/` を Playwright ワークスペース(独自の `package.json`)にした。UI 層は `web/tests/e2e/` に据え置く。

```
e2e/
  playwright.config.ts        # API 層(既定)
  playwright.edge.config.ts   # エッジ層(前提が違うので別 config = 既定では走らない)
  global-teardown.ts
  support/                    # 共有ヘルパ(env / types / moka-api / sse / assertions / compose / fixture-files / session-cookie)
  tests/setup/                # health gate(setup プロジェクト)
  tests/api/01..12-*.spec.ts  # 旧 hurl/core/**
  tests/edge/01-edge-auth.spec.ts  # 旧 hurl/edge/**
  fixtures/  mock-llm/        # 変更なし
```

設計上の決定:

**1. bash + hurl の 2 ファイル構成を 1 spec に畳む。** 状態遷移(`serveFixture` / `touchFixture` / `psql` / `stopService`)もアサーションも同じ TypeScript ファイルに書く。`child_process` を呼ぶのは `support/compose.ts` だけに閉じ、テスト用の特権操作であることを型と場所で示す。

**2. 実行順序はファイル名の 2 桁ゼロ埋め連番。** Playwright は `fullyParallel: false` **かつ** `workers: 1` のときにファイルをパスの**辞書順**で直列実行する(`runner/projectUtils.ts` が `localeCompare` でソートしている)。辞書順であって数値順ではないため、桁数を固定しないと `10-` が `2-` より前に来る。旧 README / CI が hurl のコマンドライン引数順で表現していた依存関係が、ファイル名として一箇所に固定された。

**3. `retries: 0`。** フレッシュ DB 前提の「ちょうど N 件」を主張するスイートで、途中まで DB を変えた状態からの再試行は再現性を持たない。ファイル内は `mode: 'serial'` にして、1 つ落ちたら後続をスキップする(Hurl の既定 fail-fast と同じ挙動)。

**4. health gate は setup プロジェクトへ集約。** 旧 hurl 群は各ファイル冒頭に `retry: 10` 付きの `GET /healthz` を重複して書いていた。Playwright では公式に推奨されるプロジェクト依存(`dependencies: ['setup']`)で 1 回に集約できる。

**5. エッジは別 config。** エッジ層だけ前提が違う(`compose.e2e.yaml` が不要で、代わりに本番スタックの Plecto Phase 2 配線が要る)。同一 config のプロジェクトにすると `pnpm test` が常にエッジも巻き込むので、`playwright.edge.config.ts` に分けて opt-in にした。

**6. `openssl` によるセッション cookie 鋳造を `node:crypto` に置換。** `createHmac('sha256', secret).digest('base64url')` は RFC 4648 §5 のパディング無し = Go の `base64.RawURLEncoding` と一致する。旧シェル(`openssl dgst | base64 | tr '+/' '-_' | tr -d '='`)と**バイト一致**することを実測で確認した。ついでに鍵の trim が Go 側(`strings.TrimSpace` = 端のみ)と揃った —— 旧シェルは `tr -d '[:space:]'` で内部の空白まで落としており、hex 鍵では等価だが契約としてはズレていた。

検討した代替案と却下理由:

- **Hurl を残して bash だけ削る**: bash が担っていたのは「DB 直接操作」「配信内容の差し替え」「コンテナ停止」であり、Hurl にはそれを表現する手段が無い(意図的にそう設計されている)。bash を消すなら Hurl も一緒に消えるしかない
- **API 層も `web/` の Playwright に同居させる**: インフラ追加はゼロで済むが、バックエンド API とエッジのテストが SvelteKit アプリ配下に住むことになり、`web` ジョブの paths-filter とも噛み合わない。`e2e/` は既に fixtures と mock-llm を持つ E2E の家なので、そこをワークスペース化するほうが境界として正しい
- **UI 層も `e2e/` へ集約して完全に一本化する**: 共有ヘルパを 1 箇所に持てる利点はあるが、`web/` の開発者が `pnpm test:e2e` を自分の足元で走らせる導線が失われ、差分も大きくなる。層ごとの家(API/エッジ = `e2e/`、UI = `web/`)を保つほうがミニマリズムに適うと判断した
- **`k6` / `bruno` / `vitest + supertest` 等**: 実行系を 1 つに減らすのが目的なのに、既に UI 層で使っている Playwright 以外を選ぶと本末転倒。Playwright の `APIRequestContext` は「サーバ API のテスト」を公式に第一級のユースケースとして挙げている
- **Playwright 1.62 の `lock` オプションで `workers: 1` を緩める**: ファイル・worker・プロジェクトを跨ぐ排他を宣言でき、DB を触らないテストは並列のまま残せる。ただし本スイートは**排他ではなく順序**に依存している(01 が入れた 25 記事が 05/06 のカウントの基準)ため、`lock` では置き換えられない。順序依存そのものを解く(記事件数のアサーションをフィード単位にスコープする)のが先で、それは別の変更

## Consequences

### Pros

- **1 シナリオ = 1 ファイル**になった。旧構成の 6 組の bash + hurl 往復が消え、状態遷移とアサーションが同じ場所に並ぶ
- **SSE の順序を表明できるようになった**。`support/sse.ts` の `sseEventNames()` で `sources` が最初・`done` が最後・`error` を含まない、まで書ける。旧 `body contains` では表現できなかった契約
- **CI が全シナリオを走らせるようになった**。旧 CI は README の 8 ステップのうち 5 本しか実行していなかった(`search` / `qa` / `dedupe` / `enrich` / `qa_context_relevance` / `rag_failsoft` は未実行)。Playwright では `pnpm test` 1 コマンドで全部走り、ステップの追加が CI の編集を要求しない
- **ETag の busting が決定的になった**。`fixture-files.ts` が mtime を必ず `max(now, 現在の mtime + 1 秒)` へ進めるので、nginx の秒精度 ETag が必ず変わる。旧 bash の暗黙依存が消えた
- **型と lint が掛かるようになった**。`tsc --noEmit` + ESLint(`eslint-plugin-playwright` の `no-wait-for-timeout` / `missing-playwright-await` 込み)+ Prettier が CI パリティに入った。API レスポンス封筒は `support/types.ts` で `core/internal/httpapi` の `writeJSON` と 1:1 に型付けされている
- **CI から Hurl / jq / openssl への依存が消えた**。API 層はブラウザも起動しない(`request` フィクスチャのみ)ので `playwright install` も不要
- **トレースが録れる**。失敗時に Playwright のトレースビューアで API 呼び出しの request/response を追える(Hurl には無かった)

### Cons / Tradeoffs

- **HTTP/2 · HTTP/3 の経路を踏めなくなった。** Playwright の `APIRequestContext` は Node の `http`/`https` 実装で **HTTP/1.1 のみ**を喋る([playwright#31730](https://github.com/microsoft/playwright/issues/31730) は未実装のままクローズ)。Hurl は libcurl ベースで `--http2` / `--http3` を持っていた。ただし**旧 `edge_auth.hurl` は h2/h3 を明示的に検証していなかった**ため、実際に失われたカバレッジはゼロ。Plecto は tenets §3 で HTTP/1·2·3 を担うと定義されており、その経路の検証は Plecto 側のテストと、ブラウザ経由で h2 を通る UI 層が受け持つ。**エッジの h2/h3 疎通を moka-1 側で明示的に守りたくなったら、`node:http2` を直接使う spec を 1 本足す**(依存追加なしで書ける)
- **宣言的でなくなった。** Hurl の `.hurl` は非プログラマにも読める形式だった。TypeScript の spec は表現力と引き換えに、読むのに JavaScript の知識が要る。`support/` に手続きを閉じ込め、spec 側には主張だけを残すことで緩和しているが、行数は増えた
- **Ctrl-C(SIGINT)での後始末が完全ではない。** `12-rag-failsoft.spec.ts` は `e2e-llm-mock` を止めるが、`test.afterAll` も teardown プロジェクトも SIGINT では走らない(実測で確認)。`globalTeardown`(SIGINT でも走る)に冪等な `docker compose start e2e-llm-mock` の安全網を置いて二重化したが、`SIGKILL` は救えない。旧 bash の `trap ... EXIT` も同じ穴を持っていたので後退ではない
- **`e2e/` に node_modules が増えた。** `web/` と合わせて Playwright のインストールが 2 箇所になり、バージョンの同期が手作業になる(どちらも `^1.61.1`)。片方だけ上げると挙動が分岐しうる
- **CI の e2e ジョブが長くなった。** 走らせるシナリオが 5 本から 13 本へ増え、埋め込み完了待ち(最大 120 秒)を含む。`timeout-minutes` を 20 → 30 に広げた

## Revisit Triggers

- **エッジの HTTP/2 · HTTP/3 経路を moka-1 側で守りたくなったとき** —— `node:http2` の ALPN 疎通 spec を `tests/edge/` に足す。QUIC(h3)は Node に標準クライアントが無いので、その時点で別途判断する
- **Playwright が `APIRequestContext.bodyAsStream()` を実装したとき**([playwright#17199](https://github.com/microsoft/playwright/issues/17199)) —— 現状 SSE はストリームが閉じるまでリクエストが解決しないため、「N 個目のイベントで打ち切る」「初回バイトまでのレイテンシを測る」が書けない。実装されたら `support/sse.ts` をストリーミング読みへ寄せる
- **記事件数のアサーションをフィード単位にスコープできたとき** —— 順序依存が消えるので `workers: 1` を捨て、Playwright 1.62 の `lock` による排他へ移行できる。ファイル連番という規約も不要になる
- **`e2e/` と `web/` の Playwright バージョンが乖離したとき** —— pnpm workspace 化してバージョンを 1 箇所に固定することを検討する
- **UI 層のパスキー E2E を書き直すとき** —— Playwright 1.61 で `browserContext.credentials`(仮想オーセンティケータ)が一級 API になった。現在の `web/tests/e2e/07-auth-login.spec.ts` は CDP 直叩きで Chromium 限定であり、`storageState({ credentials: true })` に置き換えれば 07 → 08 のファイル順依存も宣言的に解ける
